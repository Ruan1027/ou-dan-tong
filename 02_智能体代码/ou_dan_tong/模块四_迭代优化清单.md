## 二、迭代优化项（核心交付）

### 🔴 P0 · 本周（建议优先，其中 ①②③ 可直接动手）

**① 修 BUG-06：变更后原文依据未同步（归责 队友D/C）** ⚠️ 最高优先
- 问题：队友B 缺陷看板登记（PR#6），update 后"原文依据"未同步到查询/履历展示。
- 根因方向：`changes[]` 每项有 `source` 字段（`_format_change` 已展示 📎 原文），但建单/更新路径里 `source` 是否每次都写入、查询卡片里是否展示最新一次依据，需对齐队友D 的台账写入侧（`store.update_order` / `apply_change`）。
- 动作：① 与队友D 对齐 `changes[].source` 写入契约（更新时带用户原话）；② 模块四侧在查询卡片/最新状态处展示"依据：最新用户原话"。
- 验收：走查场景"改数量后再问最新状态"→ 卡片同时展示最新数量 + 本次变更的原文依据。
- 来源：provenance 最佳实践"记录每个槽位值来自哪一轮、支持回退调试"（[DST guide](https://articles.shadecoder.com/dialogue-state-tracking-a-comprehensive-guide-for-2025)）

**② 查询多命中 → 澄清追问（而非一次性罗列）**
- 问题：`query()` 第 5 步命中多个直接全部输出；多个客户/产品并列时用户要看半天。
- 动作：命中 >1 且无强区分（如客户字段命中多个）时，先反问"您指的是 XX（订单号）还是 YY？"，单命中才展开；加 `_needs_disambiguation()` 判定。
- 验收：test_module4 新增场景：问"老王的单"（两个老王订单）→ 走澄清分支；只命中 1 单 → 正常展开。
- 来源："低置信槽位先澄清而非自动填充"、"soft prompts 先问最不打扰的澄清"（[Slot filling guide](https://articles.shadecoder.com/slot-filling-a-comprehensive-guide-for-2025)、[ChatbotGen](https://blog.chatbotgen.com/chatbot-best-practice/)）

**③ 口语化输出后事实一致性硬校验（防幻觉再加固）**
- 问题：现在 `_colloquialize` 靠 system prompt 约束 + 长度兜底，无输出后校验；研究显示纯 prompt 只能降 37–56% 幻觉。
- 动作：写 `_check_facts(raw, rewritten)` —— 抽取两边的数字/日期/客户名/产品名/状态词，用轻量正则做集合比对，缺项或比例超阈值 → 回退原文（检测-修正管线，不依赖第二个 LLM）。
- 验收：防幻觉测试从"prompt 约束"升级为"改后事实集合 ⊇ 原文事实集合"的断言。
- 来源：RAG Triad 的 groundedness 维度（[Clarion](https://clarion.ai/?p=5019)）、检测-修正管线（[AI Wiki hallucination](https://aiwiki.ai/wiki/hallucination/revisions/3)）

**④ 测试集三层化：golden / 回归 smoke / 失败样本**
- 问题：`test_module4.py` 36 条是"全平铺"，无难度分级、无"每次改查询代码必跑"的快速集。
- 动作：分档标注（Easy 常规 / Medium 别名歧义 / Hard 冲突+多意图）；抽 10–15 条超快 smoke（每次动 query/prompt 先跑）；写 `collect_failures.md` 记录线上/演示失败问法 → 补进 golden。
- 验收：README 说明三层用途；smoke < 2 秒跑完。
- 来源："golden set 50–200 条起步、smoke 10–30 条、失败样本持续并入，三个月不增长的 golden set 是废的"（[LLM Eval Harness guide](https://labhub.hopto.org/blog/culture/2026-04-15-llm-evaluation-observability-complete-guide-eval-harness-llm-judge-tracing-deep-dive-guide-2025?lang=en)、[Pylogix](https://pylogix.com/testing-non-deterministic-software/)）

### 🟡 P1 · 一~两周（质量增强）

**⑤ 客户/产品别名规范化**
- 问题：客户用"前2字前缀"匹配，产品用"3字滑窗"，别名/简称误命中多。
- 动作：加 `customer_aliases` / `product_aliases` 配置表 + 规范化函数；匹配前先归一（去空格/全半角），别名命中与全名命中同权。
- 来源："把表面形式规范化为标准值（'下周五'→日期）再更新状态"（[DST guide](https://articles.shadecoder.com/dialogue-state-tracking-a-comprehensive-guide-for-2025)）

**⑥ 状态词表抽离为单一事实源（对齐队友D/队友A）**
- 问题：`status_keywords`/`_status_emoji` 硬编码在 `agent.py`；模块三状态机、模块一生成器各自维护。
- 动作：把状态枚举 + 关键词 + emoji 抽到 `contracts.py`（或单独 `status_meta.py`），三方共用；加一致性测试（模块三写入的状态，模块四都能命中关键词）。
- 来源："统一 slot schema：名称/类型/约束 + 穷示例 + 反例"（[Slot filling guide](https://articles.shadecoder.com/slot-filling-a-comprehensive-guide-for-2025)）

**⑦ 轻量会话上下文（指代消解，"那单/它"）**
- 问题：`query()` 单轮无状态；用户说"那单的客户叫啥"时无上下文。
- 动作：`handle_message` 层维护 per-会话 last_candidates（最近一次 query 命中的订单），检测指代词（那单/它/这单/刚才的）时优先在其上解析；会话 10 分钟过期。
- 验收：同一对话两连问："XX 到哪了"→"那单的交付日期呢" 第二条能答上。
- 来源：DST 多轮上下文携带（[DST guide](https://articles.shadecoder.com/dialogue-state-tracking-a-comprehensive-guide-for-2025)、[CSDN 智能客服架构](https://blog.csdn.net/2600_94960228/article/details/159000567)）

**⑧ 日志埋点 + 失败样本收集**
- 问题：查询命中过程、口语化是否回退、日期解析命中全部无痕，演示/排障靠肉眼。
- 动作：`query/_colloquialize` 加轻量结构化日志（question → intent → hits → 口语化回退与否 → 耗时）；WEB 端 debug 模式可见。
- 来源："上线前先埋探针，没有基线就无法证明改进、发现回归"（[Clarion](https://clarion.ai/?p=5019)）、"收集用户'这没用'类反馈作为修复优先级信号"（[DST guide](https://articles.shadecoder.com/dialogue-state-tracking-a-comprehensive-guide-for-2025)）

### 🟢 P2 · 演示加分 / 长远（可选）

**⑨ LLM-as-judge 口语化评测基线**：有 key 时按 rubric 给口语化输出打分（关键实体保留 / 无新增事实 / 自然度），用 binary 问法（研究：binary 比 1-10 分更稳），3 次取均值 + 记录基线，prompt/模型变更后重校准。
来源：[LANL judge guide](https://galileo.ai/blog/mt-bench-chatbot-arena-benchmarking-llm-judge)、[Pertama](https://www.pertamapartners.com/prompt-engineering/prompting-evaluation-testing)

**⑩ 简报阈值可配置**：临期 3 天 / 新单口径硬编码 → 提到 config（`config.py`），每次调阈值跑回归。
来源："策略写成规则而非让模型复述"（[blits.ai](https://www.blits.ai/ai-use-cases/order-status-and-returns-agent)）

**⑪ 卡片结构化渲染（去掉 replace hack）**：`_highlight_query_text` 用字符串替换高亮较脆 → 与队友A 协商 `prompts.py` 支持结构化字段或前端渲染。

**⑫ CI 接入**：GitHub Actions 跑三层测试（smoke 每次 PR / golden 定时），质量门槛（研究建议：指标回退 >5% 阻止合并）。

## 三、方法论备注（防坑）

- **非确定性输出测试**：口语化（有 LLM）断言做 3–5 跑取均值 + 容差带宽，单次失败先评论、连续 3 次失败才红 —— 避免"狼来了"关掉测试（[Pylogix](https://pylogix.com/testing-non-deterministic-software/)）
- **评测集维护节奏**：每月并入线上/演示失败样本，3 个月不增长 = 在测一个不存在的系统（[Eval guide](https://labhub.hopto.org/blog/culture/2026-04-15-llm-evaluation-observability-complete-guide-eval-harness-llm-judge-tracing-deep-dive-guide-2025?lang=en)）
- **查询 = 读系统而非编故事**：查不到 → 明确"暂无"，给引导，绝不猜单号/状态（[yehonatandev](https://yehonatandev.com/blog/ai-chatbot-for-customer-service)、[blits.ai](https://www.blits.ai/ai-use-cases/order-status-and-returns-agent)）
