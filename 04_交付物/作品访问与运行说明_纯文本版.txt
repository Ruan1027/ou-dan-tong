瓯单通 · 作品访问与运行说明

2026 第六届 INTERCITY HACK 温州站 · 瓯客松｜赛道：AI＋企业智能体
项目：瓯单通（Odt Agent）—— 把散落在微信群里的订单和任务，自动变成一张实时、可查询、可提醒的协同台账。


一、如何进入核心功能

瓯单通是一个纯本地 Web 应用，双击启动后浏览器自动打开操作界面，无需登录、无需注册、无需联网。

1. 解压完整交付包（AI+企业智能体赛道_XO_瓯单通（Odt Agent）.zip，请整包解压，勿只取部分文件）
2. 双击根目录下的「启动_Windows.bat」（macOS / Linux 用户执行 bash 启动_Mac_Linux.sh）
3. 脚本自动启动本地服务，5 秒后浏览器自动打开 http://127.0.0.1:8000
4. 页面即核心功能界面，包含两个标签页：
   · 💬 微信沟通 —— 还原微信群聊窗口，左侧为客户发来的消息，右侧为瓯单通自动提取并回写的结构化卡片
   · 📊 平台汇总 —— 实时协同台账，展示所有订单的状态、数量、交期、变更履历，可查询、可重置

无需测试账号：本作品为纯本地原型，不设登录环节，评委直接双击即可访问全部功能。


二、适用设备与系统

· 操作系统：Windows 10/11（双击「启动_Windows.bat」）；macOS / Linux（终端执行 bash 启动_Mac_Linux.sh）
· Python：3.10 及以上（启动器自带版本检查，过低会明确提示并退出）
· 浏览器：Chrome / Edge / Firefox 任意现代浏览器
· 网络：不需要外网。默认模拟模式零配置、零费用即可完整演示全部流程
· 硬件：普通笔记本即可，无特殊要求


三、运行环境与依赖服务

· 运行时依赖：纯 Python 标准库（http.server、json、re、datetime 等），无需 pip install 任何第三方包
· 数据存储：本地 JSON 文件（runtime/orders.json、runtime/tasks.json），首次运行自动生成，无数据库、无外部服务
· 大模型：
  · 模拟模式（默认，未配置 API Key）：使用预置演示数据，完整展示「提取 → 校验 → 入库 → 查询 → 简报」全流程，零费用零配置
  · 真实模式（可选）：设置环境变量 DEEPSEEK_API_KEY 后重启，可抽取任意真实群聊文本（费用走评委自己的 Key，约几分钱/百次）
· 依赖服务：无。不依赖数据库、消息队列、Redis 或任何外部服务


四、启动步骤

方式一：Windows 一键启动（推荐）
1. 解压完整交付包
2. 双击「启动_Windows.bat」
3. 浏览器自动打开 http://127.0.0.1:8000

启动成功后终端窗口显示：

  ============================================
    OU DAN TONG  /  Order Task Co-pilot
  ============================================
  Folder  : ...\ou_dan_tong
  Starting local service ...
  Then open your browser and visit:
        http://127.0.0.1:8000

方式二：macOS / Linux
# 解压后进入目录
bash 启动_Mac_Linux.sh
# 浏览器手动访问 http://127.0.0.1:8000

方式三：手动启动
cd ou_dan_tong
python web_app.py
# 浏览器访问 http://127.0.0.1:8000

保持终端窗口打开即服务运行中；关闭窗口 = 停止服务。

六、具体案例：客户数据冲突（先调出台账数据再询问）

以「⚠️ 客户数据冲突」场景为例，完整展示输入 → 处理 → 输出。

【输入】
客户在微信群发来消息：
「小陈，法兰 DN80 那单单价你按 18 算，上次说好的」
（发送人：王总。台账中已有王总的法兰订单，单价记录为 18.5）

【处理过程】
1. 意图识别：系统识别「按 18 算」为变更意图，判定为订单更新
2. 实体抽取：提取客户=王总、产品=法兰 DN80、单价=18
3. 台账匹配：按客户+产品匹配到在途单（台账单价 18.5）
4. 冲突判定：来单单价 18 ≠ 台账 18.5，validator 判定为「数值矛盾」，不自动覆盖
5. 生成冲突卡片：先调出台账真实数据展示，再询问客户是否以此为准

【输出（系统回复）】

⚠️ 冲突待确认 ORD-20261024-07
── 我们台账中记录的订单数据 ──
🔖 订单号：ORD-20261024-07
👤 客户：王总
📦 产品：法兰
💰 单价：18.5
📊 数量：×300
📅 交期：2026-11-15
📌 状态：已确认
── 矛盾点 ──
检测到与在途单数值矛盾（单价：台账 18.5 ↔ 来单 18），未自动覆盖，请人工确认以哪份为准。
❓ 请确认：是否就是这个订单？数据以我们台账记录的为准。

· 回复「是的 / 确认」→ 以台账数据为准，不做更改；
· 回复「不是 / 不同意」→ 检测到订单存在疑问，接下来将转接人工。

【后续交互】
· 客户回复「是的」→ 系统确认以台账数据为准，不做更改
· 客户回复「不是」→ 系统回复「检测到订单存在疑问，接下来将转接人工。」
此时切到「📊 平台汇总」标签页，可看到台账数据未被覆盖，保持了准确性。


七、故障恢复

· 双击 bat 报 Python version too old：系统 Python 低于 3.10 → 安装 Python 3.10+（python.org 下载，安装时勾选 Add to PATH）
· 双击 bat 报 Cannot find web_app.py：只解压了部分文件 → 请整包解压后再双击 bat
· 页面打不开 / 一直转圈：服务未启动或端口被占 → 确认终端窗口仍开着；若 8000 端口被占，编辑 web_app.py 末尾修改端口号
· 演示数据乱了想重置：多轮操作后台账变化 → 在「📊 平台汇总」标签页点击重置按钮，恢复 5 单初始种子数据
· 查询返回旧数据：浏览器缓存 → 强制刷新页面（Ctrl+F5）
· 真实模式报「未检测到 API Key」：未配置环境变量 → 模拟模式无需 Key；如需真实模式，终端执行 set DEEPSEEK_API_KEY=你的Key 后重新启动
· 页面显示「已由本地规则引擎即时判定」：真实模式下大模型网关超时 → 非故障：系统自动降级到本地规则引擎，结论与台账写入均有效，重发一次即可走真实大模型


八、数据来源与模拟范围

【数据来源】
· 演示种子订单（5 单）：自建样例（sim_chats.py → WEB_DEMO_SEED）。基于温州五金/汽配行业真实业务场景虚构的客户、产品、数量、交期，覆盖「已确认/沟通中/生产中」等多种状态
· 6 个演示场景消息：自建样例（sim_chats.py → CHAT_SCENARIOS）。模拟客户在微信群中发出的典型消息，覆盖新建/改数量/追加/缺失/冲突/异常六类场景
· 对应的抽取结果（Mock）：模拟接口（sim_chats.py → WEB_SCENARIO_MOCKS）。模拟大模型对每条消息的结构化抽取输出，无 Key 时用此 Mock 走完整管线
· 查询/简报：实时计算，无预置数据。基于台账中实时订单数据生成

【模拟范围】
· 消息抽取：模拟模式=模拟（用预置 Mock 数据替代 LLM 抽取）；真实模式=真实（调用 DeepSeek / OpenAI 兼容 API 抽取）
· 实体校验：模拟模式=真实（validator.py 确定性规则引擎，与生产环境完全一致）；真实模式=真实
· 变更比对：模拟模式=真实（apply_change 逐字段比对 + 变更履历）；真实模式=真实
· 冲突/缺失/异常判定：模拟模式=真实（四级判定 ok/missing/conflict/abnormal）；真实模式=真实
· 台账读写：模拟模式=真实（本地 JSON 存储，与生产环境完全一致）；真实模式=真实
· 查询/简报：模拟模式=真实（基于实时台账数据计算）；真实模式=真实
· 口语化改写：模拟模式=提示未生效（提示「模拟模式下口语化未启用」）；真实模式=真实（调用 LLM 将模板话术改写为口语）

核心结论：模拟模式仅「消息抽取」和「口语化改写」两个环节使用模拟数据/降级，其余校验、变更、台账、查询、简报等核心逻辑均为真实代码运行，与生产环境行为一致。

【大模型 API 说明】
· 默认使用 DeepSeek（deepseek-chat 模型，OpenAI 兼容接口）
· 也支持任意 OpenAI 兼容端点（智谱/MiniMax/通义等），设置 OPENAI_BASE_URL + OPENAI_API_KEY + OPENAI_MODEL 即可切换
· Key 通过环境变量或同级 .env 文件配置，不硬编码在代码中
· 费用极低：约几分钱/百次调用


九、尚未实现的功能

· 多用户权限管理：未实现。当前为单机演示原型，无登录/角色/权限体系
· 消息推送/主动提醒：未实现。简报需手动点击生成，无定时推送或到期自动提醒

· 数据持久化到云端：未实现。当前使用本地 JSON 文件存储，无云端同步；服务重启后可重置恢复种子数据
· 移动端适配：未实现。界面为桌面浏览器设计，未做移动端响应式适配
· 多语言支持：未实现。当前仅支持中文消息处理
